## 评论接口

### 评论列表

获取某篇文章对应的评论列表

```http
GET /api/comment
```

**参数**:

| 字段     | 类型   | 描述                                                                                                           |
| -------- | ------ | -------------------------------------------------------------------------------------------------------------- |
| path     | string | 获取对应文章标识的评论列表                                                                                     |
| page     | number | 评论列表的页数                                                                                                 |
| pageSize | number | 每页评论列表的条数                                                                                             |
| sortBy   | string | 评论排序方式，默认按时间倒序(insertedAt_desc)，还可以选择按时间正序（insertedAt_asc），按热度倒序（like_desc） |

`like_desc` 按整串讨论的**主评论点赞数＋公开回复数＋公开回复点赞数**排序，包含各层回复。待审核、垃圾评论及其他页面的回复不计入热度，即使当前用户有权限看到这些评论也一样。置顶评论仍排在最前面；同分时按评论 ID 倒序排列。返回的 `like` 仍代表该条评论本身的点赞数。

热度在查询时、分页前计算，已有评论及后续点赞、审核、删除、数据导入都不需要额外回填。SQL、MongoDB 与 CloudBase 在数据库内完成排序；GitHub 存储原本就会将 CSV 加载到内存。旧版 LeanCloud 后端则读取该文章下所有评论的排序字段，在内存中排序后才读取当前分页的评论内容，因此资源成本会随评论数增加。

已有 SQL 数据库建议新增 `(rid, url, status)` 索引，避免每个主评论都扫描整张表；新部署的 SQL 模板已包含索引。例如（请根据部署调整数据表名称与前缀）：

```sql
CREATE INDEX idx_comment_rid_url_status ON wl_Comment (rid, url, status);
```

MongoDB／CloudBase 请建立相同字段顺序的复合索引。

### 评论数

获取某篇文章对应的评论总数

```http
GET /api/comment?type=count
```

**参数**:

| 字段 | 类型   | 描述                                                 |
| ---- | ------ | ---------------------------------------------------- |
| url  | string | 获取对应文章标识的评论列表，如果为空会返回全站评论数 |

### 最近评论

获取当前网站的最近评论

```http
GET /api/comment?type=recent
```

**参数**:

| 字段  | 类型   | 描述               |
| ----- | ------ | ------------------ |
| count | number | 返回最新评论的条数 |

### 发布评论

发布一条评论

```http
POST /api/comment
```

**参数**:

| 字段    | 类型   | 描述                         |
| ------- | ------ | ---------------------------- |
| comment | string | 评论内容                     |
| link    | string | 用户输入的网站               |
| mail    | string | 用户输入的邮箱               |
| nick    | string | 用户输入的昵称               |
| pid     | string | 该条评论回复的评论 objectId  |
| rid     | string | 该条评论的根评论 objectId    |
| ua      | string | 用户的 user agent            |
| url     | string | 评论的文章标识               |
| at      | string | 该条评论回复的评论的作者昵称 |

## 阅读统计接口

### 获取阅读统计数

获取某篇文章或者多篇文章对应的阅读数

```http
GET /api/article
```

**参数**:

| 字段 | 类型   | 描述                               |
| ---- | ------ | ---------------------------------- |
| path | string | 对应文章标识，多个标识使用逗号拼接 |

### 更新阅读统计数

更新某篇文章的阅读数

```http
POST /api/article
```

**参数**:

| 字段 | 类型   | 描述         |
| ---- | ------ | ------------ |
| path | string | 对应文章标识 |
